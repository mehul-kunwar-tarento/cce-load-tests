# Implementation Plan: Node tooling core

**Branch**: n/a (folder only; suggested branch feature/node-tooling-core) · **Date**: 2026-11-06 ·
**Spec**: [spec.md](spec.md) · **Tasks**: [tasks.md](tasks.md) · **Contract**: `specs/000-performance-testing-setup/plan.md`

## Approach

- **One source of truth for settings**: `config/settings/defaults.json` describes every setting; only
  `tools/core/settings.mjs` resolves, types and derives them; `tools/core/run-setup.mjs` adds the dataset and the
  plan-definition set in the right order (so `settings`, `run` and `inspect-k6` resolve identically); k6 receives
  the result in `run-context.json`.
- **Small modules with injected side effects**: every module that would talk to Docker, Postgres, Kafka, HTTP or
  the clock takes its client/function as a parameter (with a real default); commands take an optional `deps`
  argument. The unit tests use fakes everywhere, and the whole `run` lifecycle is tested end to end with them, so
  the build never connects to anything (D14).
- **A1 and A3 are built in parallel**: A1's pure k6 modules are loaded through `tools/core/lib-bridge.mjs`
  (top-level `await import` with a clear "A1 module missing" error instead of a crash at import time); A3's
  modules are imported lazily where they are used and their absence is a warning (dry-run, settings,
  conditions) or a clear refusal (a real run that needs preflight).
- **JSON in, JSON out**: `result.json` is the only input of reports and baselines (plus `baseline-comparison.json`
  when present); Markdown is rendered and never read back. A unit test asserts the report modules read no files.
- **Ported from v1, with the lessons fixed**: settings (`lib/settings.sh` → typed resolver, durations that
  fail loudly), docker invocation (`run.sh` → `buildDockerArgs` with `--name`, `--address`, remote write),
  reports (`report-round.sh`/`report-summary.sh` jq/grep over Markdown → `run-report.mjs`/`series-report.mjs`
  over JSON), baselines (`baseline.sh` → store/compare with ≥ 3 runs, unit floors and condition warnings), the
  catch-up give-up bug (never a numeric catch-up when not caught up), the `dropped == 0` rule (now < 0.1 % and
  "k6 limit" wording), `RUN_ID` without a year (now `yyyymmdd-hhmmss`), the cold fine staircase (now warm-up at
  the last good level with `--refine-from`).

## Deviations / requests

1. **Helper modules added in `tools/core/`** (owned by A2): `paths.mjs`, `errors.mjs`, `command-args.mjs`,
   `lib-bridge.mjs`, `run-setup.mjs`, `run-clients.mjs`; `tools/baseline/baseline-metrics.mjs`.
   `RefusedError` lives in `errors.mjs` and is re-exported by `environment.mjs` as §6.3 requires.
2. **Command `main` takes an optional third argument `deps`** for dependency injection in tests; the §6.1
   contract (`main(argv, {stdout, stderr, cwd})`) is unchanged for callers.
3. **`defaults.json` entries may carry `"allowAuto": true`** (for `STEP_SLA_MAX_WAIT`,
   `STEP_SLA_PEAK_ALARM_RATE`); the schema documents it. `EVENT_ACTION_ID`, `EVENT_SOURCE`, `FACILITY_ID`
   default to `""` and are filled from the dataset by `applyDatasetDefaults` (source `derived`).
4. **`load` block**: in addition to the §5.2 fields, `measuredEventsSent` and `measuredEventsAccepted`
   (measured scenario only) are recorded; `averageRate` uses `measuredEventsSent`. `eventsSent` /
   `eventsAccepted` count all phases (as in the §5.2 example).
5. **Thresholds** may carry `informational: true` (e.g. B2's `matcher.drain-rate`, staircase search rules): such a
   rule is reported ("noted") but never fails the run.
6. **Level offsets**: `Level.startSeconds` (§4.1) is not relied on; the analysis computes each level's offset
   into the measured phase from the cumulative `durationSeconds`, so it works whichever origin A1 uses.
7. **k6 limit for Kafka tests**: the measured p95 exists only for HTTP; Kafka tests never report
   `k6Limited` (no latency to prove the service was fast). Recorded for B2 / open questions.
8. **`lint-headers --paths <p>…`** restricts the check to given paths. Git-ignored files are listed with the
   read-only `git ls-files --others --ignored --exclude-standard --directory` (`--directory` collapses ignored
   folders such as `node_modules/`; same set of files as §2.4's command).
9. **ShellCheck**: `run-shellcheck.mjs` uses a local `shellcheck`, else the `koalaman/shellcheck:v0.10.0`
   image if present locally; if neither is available it says "SKIPPED" and exits 0 (no image pull during lint).
   On this machine neither exists, so ShellCheck did not run during the build (`bash -n` passed).
10. **Request to A1** (met): `lib/phase-plan.js` phases carry `name`, `kind`, staircase `levels[]` with `rate`,
    `durationSeconds`, `plannedEvents`; A2 reads only those fields. A1's `k6-summary-sample.json` exists, so the
    test reading it runs (not pending).
11. **Request to A3**: `runPreflight({ environment, subjects, settings, planDefinitionSetName, clients, modules,
    resultsRoot })` is called by `run` with `modules: [module]` and `clients` in both of A3's conventions
    (`db` + `pgPool`, `scrape` + `scrapeUrl`, `http`, its own `kafkaAdmin`, `protocolApi`, `env`); `run` reads
    `checks[id = 'plan-definition-set'].data.otherActivePlanDefinitions` for the conditions snapshot; and imports
    `loadPlanDefinitionSet` (sets.mjs), `computeExpectedRows` (expected-rows.mjs), `getActivePlanDefinitions`
    (active.mjs), `createProtocolApi`/`createFetchHttp` (protocol-api.mjs), `formatPreflightTable` (preflight.mjs).
12. **Staircase verdict = capacity** (§5.2 status rules refined): a staircase ends when its per-level abortOnFail
    rules fire — by design. Those per-level rules (`{level:R}`) and the `BREAKPOINT_MAX_DROPPED` rule are marked
    `informational` ("finds the breaking point, not a verdict") and do not make the run `aborted`; the verdict is
    the added rule `breakpoint.held-up-to` (held ≥ `expectation.targetRate`, TBC). A service module may return a
    rule with the same id to replace it. Without this every collector breakpoint run would read "aborted".
13. **`--dry-run` writes nothing**: §6.2 lists "create results folder; write run-context.json" before the dry-run
    stop; the dry run instead only prints the folder it would use, uses the placeholder port 6565 (a real run picks
    a free port) and creates no folder or file, so verification never touches `results/` (D14/D18).
14. **`.prettierignore`** additionally ignores the verbatim FHIR fixtures `test-data/plan-definitions/` (A1) and
    `tools/plan-definitions/unit-tests/fixtures/v1-variants/` (A3), which §2.4 already exempts from headers;
    otherwise `npm run lint` failed on them. Owners A1/A3 may prefer to format them instead.
15. **Baseline compare output**: `baseline compare` writes `baseline-comparison.json` into each compared run folder
    and never rewrites `result.json`; `report <dir>` shows that file's comparison when `result.baselineComparison`
    is null. A run with `BASELINE=<name>` sets `result.baselineComparison` itself.
16. **Series default output**: `report --series|--latest|--since` without `--out` writes to
    `results/summary-<yyyymmdd-hhmmss>/` (git-ignored, ignored by later series reports: no result.json).
17. **Exit code of an aborted run is 1** (§5.7 has no own code for "aborted": the test did not pass).
18. **`check-data`** refuses a run folder whose `run-context.json` names another environment, keeps an `aborted`
    or `error` status, and records a note in `result.notes`.
19. **Extra result fields**: top-level `refinedFrom` (§6.2 "the result records refinedFrom"),
    `artifacts.serviceMetrics`, `artifacts.seedManifest`, `artifacts.baselineComparison`, `whatBroke[].firstAt`
    for diagnostics. All are documented in `tools/results/result.schema.json`.
20. **Request to B1–B3**: `testFile(testType)` must point at an existing script for every declared test type;
    `requires.services` drives the metrics sampler targets; `evaluate` receives the `partial` described above.
21. **For 000 T014 / C1**: `npm test` (464) and `npm run lint` pass over the whole tree at the time of writing; the
    real R9 command with the collector module (T023) remains for wave B.
